# Проверки версии 0.2

Дата: 8 ноября 2026 года. Среда: Linux x86_64, CPython **3.15.1**,
PyQt6 6.12.0, Qt runtime 6.12.0, `QT_QPA_PLATFORM=offscreen`.
Зависимости закреплены в `requirements.txt`.

## Функциональные тесты

`python -m pytest -q`: **36 passed**, 11.92 секунды в контрольном прогоне.
`python -m ruff check pyra tests`: без замечаний.
`sh -n start.sh`: без ошибок синтаксиса.

Проверяются кодировки и CRLF, сохранение прав доступа, отказ от двоичных файлов,
исключение окружений и symlink-циклов из обхода, предотвращение конфликтов при
refactor и откат при ошибке второго файла, допустимые спецификации pip,
скобки и автоотступ, движение точек останова при вставке строк, Undo с кириллицей,
комментарии строк, реальные дополнения/переходы/сигнатуры Jedi,
диагностика несохранённого текста Ruff, PTY с русским `input()`, debugpy с
breakpoint/переменными/шагом/продолжением, восстановление вкладок/курсора/breakpoints,
создание `.venv` и настоящая установка локального wheel, отладка в окружении
без debugpy, разделение предупреждений formatter и исходного текста,
остановка бесконечного вывода, переименование и использования символов,
статус/индекс/diff Git, а также `input()` в интегрированном терминале отладки.

В 0.2 добавлены проверки на реальном Python 3.15:

- Создание `.venv` выбранным Python 3.15 и отображение его версии.
- Запуск, AST-структура, диагностика и форматирование файла с `lazy import`
  и `frozendict`; Ruff получает целевую версию `py315`.
- Построение структуры без импорта Jedi и без исполнения кода проекта.
- Подсказка `math.sqrt` после `lazy import math` через реальное окружение 3.15.
- Независимость обычного запуска от анализатора и отладчика.

Те же пять новых тестов отдельно пройдены при **Python 3.12.14 у IDE и 3.15.1
у проекта**: 5 passed, 2.83 секунды. Повторить в старшем/младшем окружении:

```sh
PYRA_TEST_PYTHON315=/absolute/path/to/python3.15 python3.12 -m pytest tests/test_python315.py -q
```

Это проверка конкретных сценариев, а не полного покрытия всех новшеств языка.
Сложные подсказки и рефакторинг новых конструкций Jedi могут быть неполными.
Совместимость сторонних пакетов проекта с 3.15 зависит от самих пакетов.

Контрактный тест Windows проверяет список аргументов с пробелами и кириллицей
через имитацию API pywinpty. Готовые Windows x64 wheels зависимостей для
Python **3.15** найдены и скачаны: в том числе debugpy 1.8.22 и pywinpty 3.1.2
с тегом cp315, PyQt6 и QScintilla с совместимым ABI. Они не включены в архив.
Исполнение Windows GUI, batch-запуска и настоящего ConPTY здесь не проверено.
Free-threaded CPython для самой IDE не поддерживается.

Python выводит пять DeprecationWarning от `ptyprocess`/`os.forkpty()` о fork
из многопоточного приложения. Проверки PTY проходят; это не исключает редких
зависаний. Для длительной эксплуатации POSIX требуется проверить терминалы
под нагрузкой; создание PTY можно впоследствии вынести в отдельный helper-процесс.
В Windows используется другой backend.

## Запуск приложения и кода

Результаты: `launch-benchmark-315.json`. Повторить:

```sh
python tools/benchmark_launch.py --samples 7 --output launch-results.json
```

Оба интерпретатора в контрольном прогоне — Python 3.15.1.
GUI каждый раз создаётся в новом процессе: отсчёт начинается перед созданием
процесса Python и заканчивается сигналом после первой offscreen-отрисовки окна.
Не восстанавливается предыдущий проект; окно без открытых файлов.
Время установки зависимостей и работа композитора/монитора сюда не входят.
Файловый кеш ОС не сбрасывается. Это повторные запуски, не холодная загрузка ОС.

| Сценарий | Медиана 7 запусков | Максимум |
| --- | ---: | ---: |
| Новый процесс GUI → первая отрисовка | 168.870 мс | 201.852 мс |
| Run в IDE → первый вывод простого скрипта в PTY | 17.377 мс | 23.167 мс |
| Прямой запуск того же Python → первый вывод в pipe | 9.939 мс | 12.349 мс |

Скрипт печатает одну строку. Обычный Run создаёт свежий процесс Python и не включает
отладчик. Разница с прямым запуском включает создание PTY и обработку вывода GUI;
это не изолированный замер единственной функции IDE. Тяжёлые импорты, пользовательский
код и отладка добавляют своё время. Саму скорость алгоритма IDE не увеличивает.

## Редактирование и память

Результат: `benchmark.json`. Запуск: `python tools/benchmark.py`.
Скрипт создаёт окно, загружает файл из 10 002 строк (240 016 байт), затем вводит
200 символов с обработкой GUI-событий. В этом отдельном замере первая отрисовка
отсчитывается после старта Python, до импорта Qt и модулей IDE.

| Метрика | Результат |
| --- | ---: |
| Первая отрисовка после старта Python | 155.77 мс |
| RSS основного окна | 84.37 МиБ |
| Загрузка файла до отрисовки | 10.26 мс |
| Вставка символа и обработка GUI, медиана | 0.936 мс |
| Вставка символа и обработка GUI, p95 | 1.650 мс |
| RSS GUI после редактирования | 88.33 МиБ |

Память относится только к GUI: это **не** измерение полного дерева процессов
с Jedi, debugpy и оболочками. Время синтетического ввода не включает задержку
физической клавиатуры, дисплея и композитора. Сравнения с PyCharm/Cursor не проводились.
На реальном ноутбуке, Windows и больших рабочих проектах значения будут другими.

`preview.png` получен с настоящего окна Pyra под Python 3.15 после запуска примера
и ввода имени. Воспроизвести: `python tools/capture_preview.py`.
