# Pyra 0.2 — настольная IDE для Python

Рабочая первая версия с тёмной темой и русским интерфейсом. Редактор — нативный
QScintilla на C++; интерфейс и координация — Python + Qt. Electron, WebView,
расширения и сетевой AI-сервис не используются.

## Быстрый запуск в Windows

1. Используйте **Python 3.15 x64**, обычную сборку CPython с GIL.
   Если Python ещё не установлен: [python.org](https://www.python.org/downloads/windows/).
   Подойдут также Python 3.10–3.14. При установке включите Python Launcher (`py`).
   Устанавливать Python 3.12 дополнительно к 3.15 не требуется.
2. Полностью распакуйте архив, например в `D:\Pyra`. Не запускайте из ZIP.
3. Дважды щёлкните **start.bat**. При первом запуске он создаст `.ide-venv`
   и скачает зависимости из PyPI. Это библиотеки самой программы.
4. Нажмите **«Открыть проект…»** и выберите папку с вашим кодом.
5. В **«Пакеты» → «Выбрать Python…»** выберите нужный интерпретатор, если их несколько.
   **«Создать .venv»** создаёт окружение именно выбранной версии Python.
   Оно автоматически станет выбранным Python для запуска и установки пакетов.

Повторный запуск `start.bat` использует уже установленное окружение. Приложение
работает без интернета; сеть нужна для первой установки и скачивания пакетов.
Это исходники с автоматической настройкой окружения, не готовый `.exe`.

Если установка зависимостей не завершилась, повторно запустите `start.bat`.
Если зависимости были удалены после успешной установки, удалите файл
`.ide-venv\pyra-ready-v2` и запустите снова. Если команда `py` не найдена,
скрипт попробует команду `python`. Также доступен ручной способ:

```powershell
cd D:\Pyra
python -m venv .ide-venv
.\.ide-venv\Scripts\python.exe -m pip install -r requirements.txt
.\.ide-venv\Scripts\python.exe run.py
```

При первой установке `start.bat` предпочитает Python 3.15, затем перебирает
3.14–3.10. При повторном запуске проверки версий и установка пакетов пропускаются.
При обновлении с 0.1 существующее `.ide-venv` сохраняет свой Python; зависимости
обновляются один раз. Для запуска самой IDE на 3.15 распакуйте 0.2 в новую папку.

Для Linux/macOS: обычный CPython 3.10–3.15 и `sh start.sh`. Чтобы выбрать 3.15
при первой установке: `PYRA_BOOTSTRAP_PYTHON=python3.15 sh start.sh`.
Linux с графическим окружением может требовать системные библиотеки Qt.
Сборки free-threaded для самой IDE пока не поддерживаются.

Проверено на Linux x86_64 с **Python 3.15.1** и Qt в режиме offscreen: 36 тестов.
Отдельно проверены 5 сценариев, когда сама IDE работает на Python 3.12,
а проект — на 3.15. Windows x64 wheels зависимостей для 3.15 скачаны и проверены
на доступность; запуск и ConPTY на настоящей Windows здесь не проверялись.

## Установка библиотек

Откройте **«Пакеты»**. Вверху указан точный путь к Python: установки всегда идут
через **этот** интерпретатор, а не случайный `pip` из PATH.
Сначала создайте `.venv`, чтобы отделить зависимости проекта от системного Python.
При открытии проекта существующая `.venv` распознаётся автоматически; вручную
выбранный интерпретатор запоминается для каждой папки проекта.

В строке установки введите `requests`, `numpy>=1.26,<3` или `fastapi[standard]`,
нажмите «Установить». Ход установки и ошибки отображаются рядом. Кнопка
`requirements.txt…` позволяет выбрать конкретный файл зависимостей.
Если у выбранного Python нет pip, выполните в терминале
`python -m ensurepip --upgrade` и обновите список.

`.ide-venv` — библиотеки самой Pyra. `.venv` — библиотеки вашего проекта.
До создания окружения программа выбирает базовый Python, а не `.ide-venv`.
Не выбирайте внутренний `.ide-venv` для разработки своих проектов.

После смены Python откройте **новый** терминал: старые вкладки сохраняют исходное
окружение и рабочую папку, как обычные уже запущенные оболочки.

## Запуск и отладка

Запускается текущая вкладка. Перед запуском сохраняются изменённые файлы проекта.
Параметры задаются в **«Выполнение → Параметры запуска…»**.
Аргументы — JSON-массив: `["--port", "8080", "имя с пробелами"]`.
Так путь с пробелами передаётся как один аргумент на всех платформах.
Рабочая папка по умолчанию — корень проекта.

Поставьте точку останова щелчком в узком поле слева от строки или через F9.
Нажмите F5. На паузе вкладка «Отладка» показывает стек и переменные.
Двойной щелчок по кадру выбирает его. Объекты раскрываются по запросу;
строка снизу вычисляет выражения в выбранном кадре.

Для `input()` во время отладки переключитесь во вкладку **«Запуск» →
«Отладка · ввод/вывод»**. В обычном запуске ввод находится там же, в терминале файла.
Точки останова на пустых строках или комментариях отладчик может переносить
на следующую исполняемую строку.

Терминал Windows открывает PowerShell, Linux/macOS — `$SHELL` или bash.
Копирование/вставка: **Ctrl+Shift+C / Ctrl+Shift+V**, либо контекстное меню.
**Ctrl+C** отправляет прерывание программе. Стрелка вверх возвращает прошлые
команды. Колесо мыши листает историю экрана, до 3000 строк.

## Производительность

Нативный редактор обрабатывает текст без Python-цикла на каждый символ.
Jedi вынесен в отдельный лениво запускаемый процесс с пониженным приоритетом;
запросы объединяются, устаревшие ответы отбрасываются. Для структуры файла
достаточно AST: Jedi при этом не импортируется. Проверки запускаются с задержкой
после ввода. Ruff вызывается как нативный бинарник без промежуточного запуска Python.
Обычный запуск вызывает выбранный Python напрямую, не ждёт анализатора кода
и не подключает debugpy. Каждый запуск создаёт новый процесс Python.
Терминал рисует серии символов с общим стилем и ограничивает очередь вывода.
Дерево файлов загружается лениво. `.venv`, кеши, `.git`, `node_modules`, `build`
и `dist` не попадают в обход поиска. Плагины и AI-процессы не запускаются.

Файлы больше 1 МиБ открываются без Jedi и фонового Ruff. При открытии больше
2 МиБ выводится подтверждение; максимальный размер текстового файла — 20 МиБ.
Поиск обходит до 20 000 файлов и показывает до 1000 совпадений; пропускает
двоичные файлы и содержимое больше 1 МиБ. Результаты следует сужать запросом.

На Linux с Python 3.15.1: медиана запуска нового GUI-процесса до первой отрисовки
**169 мс**, нажатие «Запустить» → первый вывод простого скрипта **17 мс**.
Это семь повторов с прогретым файловым кешем, без отладчика и восстановления проекта,
Qt offscreen. Первая установка зависимостей в эти значения не входит.
Основное окно занимает около **84 МиБ RSS**; память анализатора, терминалов
и отладчика сюда не включена. Загрузка файла из 10 002 строк — около **10 мс**.

Подробные замеры — в `docs/benchmark.json` и `docs/launch-benchmark-315.json`,
методика и команды повторения — в `docs/VALIDATION_RU.md`.
Это не сравнение с PyCharm/Cursor и не гарантия времени
отклика на другом ноутбуке. «Ультраоптимизация» требует повторяемых измерений
на вашем железе, больших проектах и долгих сессиях.

## Границы первой версии

Это основа для дальнейшей разработки IDE с рабочими основными сценариями,
а не полная замена всем инструментам зрелых PyCharm и Cursor.
Пока нет AI-чата, генерации кода, Jupyter, удалённых интерпретаторов, SSH/Docker,
профилировщика, встроенной системы типов уровня Pyright, мультиоконного режима,
условных breakpoints и графического просмотра покрытия тестами.
Расширения и менеджер плагинов не установлены. Сервисы разделены по модулям,
чтобы добавить эти функции позже; публичного стабильного plugin API пока нет.

Подсказки Jedi анализируют сохранённые соседние файлы; активный файл — текущий
текст редактора. Если в проекте есть несохранённые изменения других вкладок,
сохраните их перед поиском использований. Рефакторинг предварительно сохраняет
файлы, показывает diff и проверяет версии перед записью. После переименования
содержимое затронутых вкладок перезагружается; общий Undo рефакторинга пока нет,
для истории проекта используйте Git.

В 0.2 проверены запуск, структура, диагностика, форматирование и простые подсказки
для `lazy import` в Python 3.15, а также выполнение `frozendict`.
Ruff получает целевую версию `py315`. При более старом Python самой IDE структура
нового синтаксиса разбирается выбранным Python проекта без выполнения его кода.
Jedi 0.20.1 ещё не заявляет полное покрытие всех новшеств 3.15: сложные подсказки
и рефакторинг новых конструкций могут быть неполными. Наличие пакета в PyPI
не гарантирует его совместимость с Python 3.15; ошибки pip видны во вкладке «Пакеты».

Бинарные файлы и текст в неизвестной кодировке автоматически не преобразуются.
Python-файлы с корректным `# coding:` сохраняют исходную кодировку. Для прочих
файлов поддерживается UTF-8. Файлы со смешанными окончаниями строк нормализуются
к выбранному LF или CRLF. Копирование широких Unicode-глифов в терминале может
отличаться от полноценного системного эмулятора.

Git-команды применяются к сохранённым файлам. Новые файлы сначала добавьте
в индекс, затем смотрите «Diff индекса». Для первого коммита настройте Git
`user.name` и `user.email` через терминал. Синхронизации с remote в интерфейсе нет;
`push`/`pull` можно запускать в терминале.

В приложении одновременно открывается одна сессия. Настройки, резервные копии
и `last_error.log` находятся в стандартной пользовательской папке данных Qt
для организации `PyraIDE`, приложения `Pyra`. Восстановление после сбоя
сохраняет только контрольные точки, созданные до сбоя, с интервалом 15 секунд.
Как обычно, исполняйте только код тех проектов, которым доверяете.

## Разработка и проверки

```powershell
.\.ide-venv\Scripts\python.exe -m pip install pytest==9.2.0
.\.ide-venv\Scripts\python.exe -m pytest -q
.\.ide-venv\Scripts\python.exe -m ruff check pyra tests
.\.ide-venv\Scripts\python.exe tools\benchmark.py
.\.ide-venv\Scripts\python.exe tools\benchmark_launch.py --samples 7
```

Тесты не скачивают пакеты из интернета: для проверки установки создают локальный
wheel и отдельную временную `.venv`. Проверки запускают реальный debugpy,
настоящий PTY и реальный Ruff. Тест Windows API использует подставной процесс
и проверяет передачу путей с пробелами; это не тест ConPTY на Windows.
Схема кода — в `ARCHITECTURE_RU.md`. Лицензия исходников — GPL-3.0-or-later;
лицензии используемых библиотек перечислены в `THIRD_PARTY.md`.
