# Pyra IDE 0.4.0 RC2 — Performance & Navigation

Кандидат v0.4 на базе v0.3: навигация по файлам `Ctrl+P`, палитра команд
`Ctrl+Shift+P`, поиск по проекту `Ctrl+Shift+F`, история переходов `Alt+←/→`,
breadcrumbs, недавние проекты, кэширование индекса файлов, ограничение очередей
фоновых запросов и облегчённый режим для крупных файлов. Тёмная тема сохраняется,
AI и плагины пока не требуются.

**Статус RC2, не финальный релиз:** в текущей среде удалось выполнить 14 независимых
тестов и измерить индекс на Linux/Python 3.13; Qt GUI, Python 3.15 и обе Windows-сборки
не перепроверены (отсутствуют зависимости Qt и доступ к их установке).
Оригинальный архив v0.4 RC1 содержал одну проваленную GUI-проверку, она скорректирована
по фактическому начальному состоянию панели; восстановление фокусного режима дополнительно
защищено от неотображённого ещё окна. **Исправление GUI не подтверждено повторным запуском.**
См. `RELEASE_REPORT_RU.md` и `docs/VALIDATION_0.4_RU.md`.

Для проверки Windows: `start.bat`, затем `build_exe.bat both` и инструкции в
`BUILD_EXE_RU.md`. Исходный архив не содержит EXE. Офлайн-работа после установки
зависимостей остаётся предусмотренным сценарием.

История и ограничения предыдущего этапа v0.3: `docs/VALIDATION_0.3_RU.md`,
`docs/VALIDATION_SIDEBAR_UI_RU.md`.

## Быстрый запуск в Windows

1. Распакуйте архив полностью. Используйте обычный CPython 3.10–3.15 с GIL.
2. Запустите `start.bat`. Первая настройка скачивает зависимости; далее IDE работает офлайн.
3. Если Python установлен на D: и отсутствует в PATH/Launcher, откройте CMD в папке проекта:

```bat
set "PYRA_BOOTSTRAP_PYTHON=D:\Python315\python.exe"
start.bat
```

Замените пример своим настоящим путём. Переменная задаёт Python для первоначальной
настройки IDE; существующая `.ide-venv` сохраняется. Скрипт не изменяет ваш системный PATH.
Для повторной установки зависимостей удалите только `.ide-venv\pyra-requirements.sha256`.

4. Откройте проект. В меню **Окружение → Python и библиотеки** нажмите **Найти Python**.
   Поиск выполняется в фоне и отменяется той же кнопкой. Проверяются окружения проекта,
   сохранённые пути, PATH, Python Launcher, реестр Windows и типичные папки всех локальных
   фиксированных дисков. Полного обхода дисков нет. Для нестандартного расположения
   нажмите **Выбрать Python…** и укажите `python.exe` на любом диске.
5. Переключайте проверенные интерпретаторы в списке. Выбор хранится для проекта;
   известные интерпретаторы доступны между запусками. Неверный выбор не заменяет рабочий.
6. **Создать .venv** использует выбранный Python. Запуск, пакеты и новые терминалы
   используют выбранное окружение; ранее открытые терминалы сохраняют свой процесс.

Без установленного Python готовая сборка открывает и редактирует файлы; для запуска,
Jedi и отладки требуется выбрать реальный Python. Служебные библиотеки включены в сборку,
установка Jedi/debugpy в окружение проекта не требуется. Указание `Pyra.exe`, `py.exe`,
`pythonw.exe` или Windows Store alias вместо Python отклоняется.

## Сборка EXE и диагностика

```bat
build_exe.bat onefile
build_exe.bat onedir
```

`onefile` создаёт `dist\onefile\Pyra.exe`; `onedir` — папку `dist\onedir\Pyra`.
Можно выполнить `build_exe.bat both`. Подробнее: `BUILD_EXE_RU.md`.
Журнал доступен в **Справка → Журнал ошибок**: просмотр, копирование, сохранение.
Логи ограничены по размеру (1 МиБ × 4 файла), исходники и переменные окружения не выгружаются.

Проверка уже собранного EXE не меняет ваши проекты или сессию:

```powershell
$p = Start-Process -FilePath '.\dist\onefile\Pyra.exe' -ArgumentList '--self-test --python "D:\Python315\python.exe" --report "D:\Pyra\selftest-onefile.json"' -Wait -PassThru
$p.ExitCode
```

Укажите существующую папку для отчёта. Self-test использует временный проект с кириллицей
и пробелами, чистую venv без служебных пакетов, GUI, Run/input(), Jedi, Ruff, debugpy,
выделение терминала и восстановление черновика, закрепления и компоновки.
Повторите для `dist\onedir\Pyra\Pyra.exe`. Код 0 и `passed: true` означают успех.
Результат при ошибке сохраняется в JSON; EXE без консоли не обязан печатать вывод.

Для Linux/macOS: `sh start.sh`; при первом запуске можно задать `PYRA_BOOTSTRAP_PYTHON`.
Тесты исходников: `python -m pip install -r requirements-dev.txt`, затем `python -m pytest -q`.
Free-threaded и версии вне CPython 3.10–3.15 этой поставкой не поддерживаются.

## Рабочее пространство v0.3

- Слева расположены подписанные разделы: **Проект**, **Поиск**, **Запуск**,
  **Отладка**, **Терминал**, **Пакеты** и **Git**; снизу — **Справка**.
  Выбранный раздел выделен фиолетовым; наведение показывает назначение и сочетания клавиш.
  **Проект** возвращает дерево файлов и переводит в него фокус; Ctrl+B скрывает/показывает дерево.
  **Запуск** открывает вывод программы, **Отладка** — стек, переменные и управление шагами.
  Для выполнения файла используйте верхнюю кнопку **Запустить** или Shift+F10;
  для начала отладки — F5. **Справка** открывает это руководство.
  В заголовке дерева кнопка **Новый файл** создаёт файл в проекте.
- Перетаскивайте разделители между деревом, структурой файла, редактором и нижней панелью.
  ПКМ по вкладке нижней панели → **Отделить панель** позволяет отдельно расположить
  терминал, Problems, «Вывод» и другие инструменты. Отделённую панель можно пристыковать
  к краю окна; её крестик возвращает панель в нижние вкладки. Положение запоминается.
- ПКМ по вкладке файла → **Закрепить** или **Ctrl+Alt+K**. Закреплённые вкладки находятся
  слева, не закрываются случайным Ctrl+W и исключаются из массового закрытия.
  Для закрытия сначала открепите файл. Ctrl+Tab / Ctrl+Shift+Tab переключают вкладки.
- **Ctrl+Alt+Z** включает режим фокуса: остаются редактор, меню и строка состояния.
  **Escape** возвращает прежнюю компоновку. **Вид → Сбросить расположение панелей**
  восстанавливает исходное расположение. Alt+1…5 переводят фокус между основными областями.
- При выходе из IDE сохраняется сессия вместе с несохранёнными буферами. Исходные файлы
  от этого не перезаписываются. После открытия вернутся вкладки, курсор, прокрутка,
  закрепление, точки останова и компоновка. Явное закрытие вкладки или смена проекта
  по-прежнему предлагает сохранить, отбросить изменения или отменить действие.
- Контрольная точка записывается в фоне через секунду после изменений; при непрерывном
  вводе — примерно раз в пять секунд. При выходе IDE ждёт успешной записи. Ошибка записи
  оставляет окно открытым. В простое сессия повторно не записывается.
  После сбоя доступны только данные последней успешно записанной контрольной точки.
- `--no-restore` не открывает старые вкладки, но сохраняет отложенные черновики.
  Их можно открыть через **Файл → Восстановить отложенные черновики**. При запуске
  с другой папкой проекта черновики прежней сессии также остаются доступными.
- **Вид → Фоновые задачи…**, **Ctrl+Alt+T**: список текущих операций и отмена.
  У поиска по проекту кнопка «Найти» меняется на «Отменить». Regex использует Qt/PCRE2
  с ограничением сложности; чрезмерно сложный запрос завершается с понятным сообщением.
  Отмена установки пакетов прекращает процессы, но не откатывает уже выполненные pip изменения.

### Ruff I001: замечание к оформлению

`I001` относится к порядку импортов и пустым строкам, а не к выполнению Python.
В приведённом примере между `import asyncio` и `async def` нужна ещё одна пустая
строка: обычно перед функцией верхнего уровня оставляют две. Ruff также учитывает
настройки проекта. В Problems теперь показаны категория **«Стиль»**, русское пояснение
и сочетание **Ctrl+Alt+L**. Стиль отмечен синим пунктиром, предупреждения — жёлтым,
ошибки — красным. Форматирование сначала безопасно приводит в порядок импорты,
затем форматирует код; весь результат отменяется одним Ctrl+Z. Неиспользуемые импорты
при этом не удаляются. Справка Ruff: https://docs.astral.sh/ruff/rules/unsorted-imports/

`RuntimeWarning: coroutine ... was never awaited` в выводе программы — отдельное
предупреждение Python. Для запуска асинхронной точки входа обычно нужен
`asyncio.run(main())`; IDE не меняет эту логику автоматически.

## Установка библиотек

Откройте **«Пакеты»**. Вверху указан точный путь к Python: установки всегда идут
через **этот** интерпретатор, а не случайный `pip` из PATH.
Сначала создайте `.venv`, чтобы отделить зависимости проекта от системного Python.
При открытии проекта существующая `.venv` распознаётся автоматически; вручную
выбранный интерпретатор запоминается для каждой папки проекта.

В строке установки введите `requests`, `numpy>=1.26,<3` или `fastapi[standard]`,
нажмите «Установить». Ход установки и ошибки отображаются рядом. Кнопка
`requirements.txt…` позволяет выбрать конкретный файл зависимостей.
Если у выбранного Python нет pip, выполните в терминале
`python -m ensurepip --upgrade` и обновите список.

`.ide-venv` — библиотеки самой Pyra. `.venv` — библиотеки вашего проекта.
До создания окружения программа выбирает базовый Python, а не `.ide-venv`.
Не выбирайте внутренний `.ide-venv` для разработки своих проектов.

После смены Python откройте **новый** терминал: старые вкладки сохраняют исходное
окружение и рабочую папку, как обычные уже запущенные оболочки.

## Запуск и отладка

Запускается текущая вкладка. Перед запуском сохраняются изменённые файлы проекта.
Параметры задаются в **«Выполнение → Параметры запуска…»**.
Аргументы — JSON-массив: `["--port", "8080", "имя с пробелами"]`.
Так путь с пробелами передаётся как один аргумент на всех платформах.
Рабочая папка по умолчанию — корень проекта.

Поставьте точку останова щелчком в узком поле слева от строки или через F9.
Нажмите F5. На паузе вкладка «Отладка» показывает стек и переменные.
Двойной щелчок по кадру выбирает его. Объекты раскрываются по запросу;
строка снизу вычисляет выражения в выбранном кадре.

Для `input()` во время отладки переключитесь во вкладку **«Запуск» →
«Отладка · ввод/вывод»**. В обычном запуске ввод находится там же, в терминале файла.
Точки останова на пустых строках или комментариях отладчик может переносить
на следующую исполняемую строку.

Терминал Windows открывает PowerShell, Linux/macOS — `$SHELL` или bash.
Копирование/вставка: **Ctrl+Shift+C / Ctrl+Shift+V**, либо контекстное меню.
**Ctrl+C** копирует выделение; без выделения отправляет прерывание программе.
Одиночный щелчок снимает выделение, двойной выбирает слово. При выделении видимый
экран фиксируется, чтобы новые строки вывода не подменили копируемый текст; сама
программа продолжает работать. **Escape**, ввод или прокрутка возвращают живой экран.
Стрелка вверх возвращает прошлые команды. Колесо мыши листает историю до 3000 строк.
Выделяется видимая область; автоматической прокрутки при протягивании мыши за её край
пока нет. При копировании визуально перенесённые строки разделяются переводом строки.

## Производительность

Нативный редактор обрабатывает текст без Python-цикла на каждый символ.
Jedi вынесен в отдельный лениво запускаемый процесс с пониженным приоритетом;
запросы объединяются, устаревшие ответы отбрасываются. Для структуры файла
достаточно AST: Jedi при этом не импортируется. Проверки запускаются с задержкой
после ввода. Ruff вызывается как нативный бинарник без промежуточного запуска Python.
Обычный запуск вызывает выбранный Python напрямую, не ждёт анализатора кода
и не подключает debugpy. Каждый запуск создаёт новый процесс Python.
Терминал рисует серии символов с общим стилем и ограничивает очередь вывода.
Дерево файлов загружается лениво. `.venv`, кеши, `.git`, `node_modules`, `build`
и `dist` не попадают в обход поиска. Плагины и AI-процессы не запускаются.

Файлы больше 1 МиБ открываются без Jedi и фонового Ruff. При открытии больше
2 МиБ выводится подтверждение; максимальный размер текстового файла — 20 МиБ.
Поиск обходит до 20 000 файлов и показывает до 1000 совпадений; пропускает
двоичные файлы и содержимое больше 1 МиБ. Результаты следует сужать запросом.

Замеры этой версии и исходные результаты — в `docs/VALIDATION_0.3_RU.md`.
Отчёты `VALIDATION_RU.md` и `VALIDATION_0.2.1_RU.md` оставлены как история предыдущих
версий. Измерения Linux/offscreen не являются обещанием скорости на Windows.

## Известные ограничения

Это основа для дальнейшей разработки IDE с рабочими основными сценариями,
а не полная замена всем инструментам зрелых PyCharm и Cursor.
Пока нет AI-чата, генерации кода, Jupyter, удалённых интерпретаторов, SSH/Docker,
профилировщика, встроенной системы типов уровня Pyright, мультиоконного режима,
условных breakpoints и графического просмотра покрытия тестами.
Расширения и менеджер плагинов не установлены. Сервисы разделены по модулям,
чтобы добавить эти функции позже; публичного стабильного plugin API пока нет.

Подсказки Jedi анализируют сохранённые соседние файлы; активный файл — текущий
текст редактора. Если в проекте есть несохранённые изменения других вкладок,
сохраните их перед поиском использований. Рефакторинг предварительно сохраняет
файлы, показывает diff и проверяет версии перед записью. После переименования
содержимое затронутых вкладок перезагружается; общий Undo рефакторинга пока нет,
для истории проекта используйте Git.

В 0.2 проверены запуск, структура, диагностика, форматирование и простые подсказки
для `lazy import` в Python 3.15, а также выполнение `frozendict`.
Ruff получает целевую версию `py315`. При более старом Python самой IDE структура
нового синтаксиса разбирается выбранным Python проекта без выполнения его кода.
Jedi 0.20.1 ещё не заявляет полное покрытие всех новшеств 3.15: сложные подсказки
и рефакторинг новых конструкций могут быть неполными. Наличие пакета в PyPI
не гарантирует его совместимость с Python 3.15; ошибки pip видны во вкладке «Пакеты».

Бинарные файлы и текст в неизвестной кодировке автоматически не преобразуются.
Python-файлы с корректным `# coding:` сохраняют исходную кодировку. Для прочих
файлов поддерживается UTF-8. Файлы со смешанными окончаниями строк нормализуются
к выбранному LF или CRLF. Копирование широких Unicode-глифов в терминале может
отличаться от полноценного системного эмулятора.

Git-команды применяются к сохранённым файлам. Новые файлы сначала добавьте
в индекс, затем смотрите «Diff индекса». Для первого коммита настройте Git
`user.name` и `user.email` через терминал. Синхронизации с remote в интерфейсе нет;
`push`/`pull` можно запускать в терминале.

В приложении одновременно открывается одна сессия. Настройки, резервные копии
и `last_error.log` находятся в стандартной пользовательской папке данных Qt
для организации `PyraIDE`, приложения `Pyra`. Сессия v0.3 хранится в `workspace-v3.json`, предыдущая контрольная точка —
`workspace-v3.previous.json`. Повреждённая основная копия сохраняется отдельно
с именем `workspace-damaged-*.json` перед восстановлением предыдущей. Старые
файлы `recovery/*.json` удаляются только после успешного переноса корректных черновиков.
При превышении лимита 256 МиБ сохраните большие буферы в файлы и повторите выход.
Как обычно, исполняйте только код тех проектов, которым доверяете.

## Разработка и проверки

Текущая приёмка: `docs/VALIDATION_0.3_RU.md`.


```powershell
.\.ide-venv\Scripts\python.exe -m pip install pytest==9.2.0
.\.ide-venv\Scripts\python.exe -m pytest -q
.\.ide-venv\Scripts\python.exe -m ruff check pyra tests
.\.ide-venv\Scripts\python.exe tools\benchmark.py
.\.ide-venv\Scripts\python.exe tools\benchmark_launch.py --samples 7
```

Тесты не скачивают пакеты из интернета: для проверки установки создают локальный
wheel и отдельную временную `.venv`. Проверки запускают реальный debugpy,
настоящий PTY и реальный Ruff. Тест Windows API использует подставной процесс
и проверяет передачу путей с пробелами; это не тест ConPTY на Windows.
Схема кода — в `ARCHITECTURE_RU.md`. Лицензия исходников — GPL-3.0-or-later;
лицензии используемых библиотек перечислены в `THIRD_PARTY.md`.
