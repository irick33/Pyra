# Pyra IDE — Roadmap

**Стартовая точка:** Pyra IDE v0.2.  
**Основная платформа:** Windows 10/11.  
**Язык пользовательских проектов:** Python.  
**Принцип:** функциональность не должна достигаться ценой отзывчивости, стабильности и сохранности данных.

> Это план, а не описание уже реализованных возможностей. До начала работы над версией необходимо свериться с фактическими исходниками и текущим CHANGELOG.

## Общие критерии качества для каждого релиза

- Измерять холодный и повторный запуск, полное потребление памяти деревом процессов, задержку ввода (в том числе p95), время открытия проекта и файлов, отклик автодополнения и запуск пользовательского кода.
- Фиксировать Windows, CPU, RAM, версию Python, тип сборки (`onefile`/`onedir`), размер проекта и условия измерения.
- Проверять работу с путями с кириллицей и пробелами, отсутствие блокировки GUI и сохранность пользовательских файлов.
- Автотесты и функциональные проверки должны покрывать изменённые сценарии. Не выдавать непроверенные функции за готовые.
- UI: компактный, информативный, с тёмной темой по умолчанию. Не добавлять декоративные элементы, анимации и панели без практической пользы.

## v0.2.1 — Windows Stability & Packaging

**Цель:** обеспечить надёжную разработку и распространение приложения на Windows.

**Функции:** обнаружение Python на любых дисках; выбор нескольких интерпретаторов; работа `venv`; корректные пути с кириллицей/пробелами; запуск кода, терминала, Jedi, Ruff и debugpy после упаковки; диагностика ошибок; сборки `onefile` и `onedir`; отсутствие жёстко заданных путей.

**UX:** понятный выбор интерпретатора, доступный журнал ошибок, уведомления с конкретными действиями по исправлению.

**Критерий готовности:** на тестовой Windows-системе приложение запускается, открывает проект и исполняет простой скрипт; проверены обе упаковки и фоновые службы.

## v0.3 — Architecture & Workspace

**Цель:** модульность и надёжное рабочее пространство.

**Функции:** декомпозиция больших оконных классов; разделение GUI и прикладной логики; управление фоновыми задачами и их отменой; обработка ошибок; сохранение сессии; восстановление несохранённых данных; тесты жизненного цикла.

**UX:** регулируемые панели дерева проекта, редактора, терминала, Problems и Output; сохранение компоновки; вкладки файлов; закрепление; Zen/Focus Mode; управление с клавиатуры.

**Критерий готовности:** длительная работа с несколькими открытыми файлами и параллельными фоновыми службами без зависаний и потери данных.

## v0.4 — Performance & Navigation

**Цель:** измеримая отзывчивость и быстрая навигация.

**Функции:** профилирование старта; ленивый запуск сервисов; кеширование; дебаунс диагностики; ограничение фоновых очередей; обработка крупных файлов; сравнение `onefile` и `onedir`.

**UX:** `Ctrl+P` поиск файлов; `Ctrl+Shift+P` палитра команд; поиск по проекту; быстрые переключения вкладок и панелей; breadcrumbs; история навигации; недавние проекты.

**Критерий готовности:** опубликованы воспроизводимые результаты производительности относительно предыдущего релиза, а поиск и ввод остаются отзывчивыми.

## v0.5 — Smart Python Editor

**Цель:** полноценная интеллектуальная работа с Python-кодом.

**Функции:** LSP и оценка Pyright; анализ типов; переход к определениям; поиск использований; рефакторинг переименования; автоматические импорты; сигнатуры и документация; быстрые исправления; интеграция форматирования Ruff.

**UX:** компактный список дополнений; подсказки параметров; `Alt+Enter` для доступных исправлений; понятная диагностика; многокурсорное редактирование и умные отступы, если они ещё не реализованы; установка отсутствующих пакетов в выбранное окружение с подтверждением.

**Критерий готовности:** корректная навигация по многофайловому проекту без заметной деградации ввода.

## v0.6 — Debugging & Testing

**Цель:** удобная отладка и тестирование без дополнительных инструментов.

**Функции:** условные breakpoints; watches; стек вызовов; просмотр значений; останов по исключениям; шаговая отладка; pytest; запуск одиночных и всех тестов; отчёты покрытия.

**UX:** понятная Debug-панель, интерактивный просмотр переменных, переход по traceback, индикация активной строки, компактный список результатов тестов.

**Критерий готовности:** отладка и тестирование реального многофайлового проекта из UI.

## v0.7 — Projects & Environments

**Цель:** создание проектов и управление окружениями без ручной конфигурации.

**Функции:** шаблоны обычного Python, FastAPI, Flask и CLI; создание `venv`; конфигурации запуска; поддержка `requirements.txt` и `pyproject.toml`; интеграция uv; оценка Poetry; установка/обновление/удаление зависимостей.

**UX:** стартовое окно и недавние проекты; компактный мастер нового проекта; выбор интерпретатора; панель библиотек; Smart Run, не запускающий неоднозначные конфигурации без подтверждения.

**Критерий готовности:** новый проект создаётся, получает окружение и запускается из UI.

## v0.8 — Git & Productivity

**Цель:** повседневная работа с Git в IDE.

**Функции:** ветки, коммиты, pull/push, история, diff, разрешение конфликтов, контролируемый откат, настраиваемые горячие клавиши.

**UX:** компактная Git-панель; статус файлов; inline diff; просмотр конфликтов и подтверждение опасных операций.

**Критерий готовности:** типичный цикл изменения—проверка diff—commit—push выполняется в Pyra.

## v0.9 — Pyra AI (опционально)

**Цель:** AI-инструменты без зависимости базовой IDE от AI.

**Функции:** чат по файлу и проекту; объяснение кода; генерация тестов и функций; предложения исправлений; многофайловые патчи; опциональные облачные API и локальные модели; отмена задач.

**UX:** скрываемая AI-панель; действия по выделению; обязательный предпросмотр diff и выборочное применение.

**Безопасность:** передача исходного кода в облако только по осознанному выбору; команды требуют разрешения; изменения откатываемы; AI не работает в фоне, если отключён.

**Критерий готовности:** AI-предложения применяются контролируемо, а без AI IDE работает без ограничений.

## v1.0 — Stable Release

**Цель:** релиз для повседневной Python-разработки.

**Функции:** регрессионное и нагрузочное тестирование; длительные сессии; аудит безопасности; Windows 10/11; установщик и portable-сборка; документация; проверяемый механизм обновлений; CI/CD; лицензии зависимостей; GitHub Releases.

**UX:** единообразие действий и терминологии; доступность и клавиатурная навигация; работа на HiDPI; прозрачная диагностика и восстановление.

**Критерий готовности:** выполнены релизные тесты, известные ограничения документированы, доступна воспроизводимая сборка.

## После 1.0

- **v1.1 — Plugin API:** стабильные расширяемые API, менеджер плагинов, контроль разрешений и изоляции, возможность отключения расширений.
- **v1.2 — Advanced Tools:** Jupyter, SSH/WSL, контейнеры, профилирование — на основании пользовательских потребностей и измерения стоимости поддержки.

## Порядок работы ИИ над релизом

1. Изучить исходники и документацию, сверить фактические возможности с планом.
2. Составить список изменений, затрагиваемых файлов, рисков и тестов.
3. Реализовать работающие изменения без заглушек и потери существующей функциональности.
4. Выполнить доступные тесты, проверить запуск и сборку там, где есть соответствующая среда.
5. Обновить README и CHANGELOG; предоставить полный проект и краткий отчёт об изменениях, тестах и непроверенных сценариях.

Версию менять только после выполнения и проверки согласованных критериев. При ограничениях среды честно обозначать, что не проверено.
