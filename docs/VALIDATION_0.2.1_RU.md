# Проверка Pyra 0.2.1 RC1

Дата: 2026-11-08. Исходная база: `Pyra_IDE_v0.2_build_ready.zip`.

**Статус:** кандидат релиза. Критерий ROADMAP для 0.2.1 требует запуска на
реальной Windows; в этой среде он не выполнен. Windows EXE здесь не собран.
Подготовлены полный проект, Windows-сборщик и автоматический self-test EXE.
Нативные Linux-бинарники использовались для проверки упаковки и в архив не включены.

Self-test создаёт временный путь с кириллицей и пробелами, venv без pip/Jedi/debugpy,
открывает настоящее окно и файл; проверяет выбор Python, Run с input() и кириллицей,
комплектные Jedi/Ruff, форматирование, breakpoint и интерактивный ввод при отладке.
Тест завершает службы, закрывает файловые дескрипторы журнала и уничтожает виджеты
до удаления временной папки. Обычные настройки сессии пользователя не затрагиваются.

В новых модульных/интеграционных тестах проверены отсутствие запуска Python в
синхронном default_python, пути D: с пробелами/кириллицей в Launcher, ограниченность
обхода папок, валидация/отмена поиска, сохранение venv symlink, отклонение неподдерживаемых
рантаймов, очистка окружения PyInstaller, повторное использование Job после таймаута,
сохранение выбора, сохранность таблицы пакетов и закрытие лог-файлов.
Исходные проверки редактора, кодировок, атомарного сохранения, recovery, refactor,
Git, интерактивной отладки, venv/pip и синтаксиса Python 3.15 сохранены.

Логи pytest: `tests-python312-project315.txt`, `tests-python315.txt`.
Результаты self-test: `selftest-source-linux.json`, `selftest-onedir-linux.json`,
`selftest-onefile-linux.json`. Рендер: `preview-environments.png`.

## Среда и метод измерений

- Linux 6.18.57 x86_64, glibc 2.41, контейнер; Qt **offscreen**, не физический дисплей.
- CPU: Intel(R) Xeon(R) Platinum 8370C CPU @ 2.80GHz; доступно логических CPU: 9.
- RAM, сообщённая средой: 9.73 ГиБ.
- Замеры: CPython 3.12.14, PyQt6/Qt 6.12.0, QScintilla 2.14.1.
- Файловый проект: 101 Python-файл; редактируемый файл — 10 002 строки / 210012 байт до правок.
- Семь запусков нового процесса для каждого режима; кеш ОС **не очищался**.
  Первый отсчёт не считается настоящим холодным стартом после перезагрузки.
- Времена включают первый paint пустого окна без восстановления проекта, сессии,
  системного lock-файла и пользовательской нагрузки; это специальный тестовый вход.
- Ввод: 200 событий QTest, замер от отправки события до обработки GUI; не аппаратная задержка клавиатуры.
- Память: сумма RSS всего дерева, включая процесс Jedi и его дочерний Python.
  Общие страницы могут учитываться несколько раз; это не PSS и не нагрузка отладчика.

Один Python 3.12.14 и одна методика `benchmark_launch.py`, по семь повторов.
Сравнение выполнялось последовательно; есть шум контейнера и кеширования.

| Метрика source | v0.2 | v0.2.1 RC1 |
| --- | ---: | ---: |
| Новый GUI-процесс до paint, медиана | 371.503 мс | 362.631 мс |

Разница не доказывает устойчивое ускорение; заметной регрессии в этих двух
коротких сценариях не обнаружено. Старые цифры из исходного архива получены
в другой сессии и не используются как сопоставимый baseline.

Полные отсчёты: `benchmark-stability-0.2.1.json`, `benchmark-launch-0.2.1.json`,
`benchmark-packaging-0.2.1.json`, `benchmark-baseline-v0.2.json`.
Команды повторения находятся в `BUILD_EXE_RU.md` и docstring каждого инструмента.

## Известные ограничения и оставшаяся приёмка

- Нет реальной Windows: не проверены EXE --windowed, ConPTY, чтение реестра,
  Windows Launcher и SetDllDirectory на этой ОС. Прямую проверку надо провести
  **для обеих упаковок** по `BUILD_EXE_RU.md` до объявления стабильной 0.2.1.
- Нет длительного нагрузочного прогона, HiDPI, физического ввода и настоящего
  холодного запуска; это не критерии готовности будущей v0.3/v1.0.
- На Linux pytest выдаёт 5 DeprecationWarning от прежнего PTY/forkpty механизма
  в многопоточном процессе. Ошибок/зависаний в выполненных сценариях не было;
  это остаётся ограничением Unix-терминала, не результатом Windows-тестирования.
- Поиск ограничен типичными папками; переносные/вложенные интерпретаторы выбираются
  вручную. Файловый I/O на проблемном диске может пережить общий временной бюджет
  поиска, но выполняется вне GUI. Сетевые/съёмные диски автоматически не сканируются.
- В сборке отладчик использует Python fallback для совместимости minor-версий;
  производительность отладки отдельно не измерялась. Обычный Run не загружает debugpy.
- Наличие Windows wheels подтверждает возможность получения зависимостей,
  но не успешный запуск на конкретном ноутбуке.
